# MAYKOP VPN Test — бесплатный тест на iPhone

Один SwiftUI target, iOS 17+, iPhone. Системный IKEv2 с EAP (логин/пароль).
Нет Network Extension, Personal VPN, App Groups, Push, iCloud и платного аккаунта.
Это прототип оболочки: статус читается в системных настройках. HTTPS-проверка
сравнивает выходной IP с ожидаемым и не выдаёт себя за NEVPNStatus.
Работа на физическом iPhone подтверждается отдельно после установки.
Версия исходников для следующей облачной сборки: 0.5 (build 5).

## Сборка на Windows через GitHub

Запустить workflow в отдельном открытом репозитории, скачать артефакт MaykopTest.
В нём unsigned IPA, SHA-256 и отчёт проверки. В публичном коде нет настроек
владельца, паролей и исходников основного VPN. CI проверяет один target,
отсутствие extensions, embedded provisioning profile и entitlements.
IPA без подписи Apple ещё не устанавливается.

## Первая установка

25.10.2026 Sideloadly 0.71.1 после кода проверки вернула -80046. На этом
компьютере вход, подпись и установка прошли через бесплатный iLoader 2.4.0.
Первый запуск после ручного доверия разработчику также проверен по USB.
Работа VPN на физическом телефоне проверяется отдельно.

1. На Windows подготовить официальные USB-компоненты Apple и iLoader с
   https://github.com/nab138/iloader/releases/tag/v2.4.0.
2. Подключить разблокированный iPhone кабелем, подтвердить доверие.
3. В iLoader войти своим бесплатным Apple Account, выбрать iPhone, нажать
   «Импорт IPA» и указать MaykopTest.ipa. Пароль и код Apple вводить лично
   в окне программы, не присылать в чат. Оставить защищённое хранилище включённым.
   iLoader добавляет App Groups даже обычному приложению; поэтому на подготовленном
   компьютере выполнить локальную переподпись без этого разрешения:

   ```powershell
   & "$env:LOCALAPPDATA/MaykopIOSResearch/usb-runtime/Scripts/python.exe" "$env:USERPROFILE/Documents/MaikopVPN-repo/deploy/ios_local_minimal_sign.py" --install
   ```

   Скрипт использует уже выданную подпись из защищённого хранилища Windows.
   Пароль Apple ему не нужен. Закрытый ключ передаётся подписывающей программе
   только в памяти через защищённый канал, в файл не записывается.
4. При необходимости доверить свою подпись в Настройки → Основные → VPN и
   управление устройством. Включить Режим разработчика, если iOS запросит.
5. Открыть MAYKOP VPN Test. Настройки сервера вводятся локально. Пароль хранится
   в обычном Keychain этого приложения, без sharing.
6. Сформировать профиль. Установка профиля всегда требует ручного подтверждения
   владельца. Передача через Share Sheet не гарантирует экран установки:
   надёжный уже проверенный путь — передать профиль по доверенному USB через
   Apple MobileConfig, затем Настройки → Профиль загружен → Установить.
7. Открыть VPN в настройках, выбрать MAYKOP iOS Test, включить. Проверить трафик
   в приложении и сопоставить его с IPsec-счётчиками отдельного тестового сервера.

Сохранение или USB-импорт настроек в приложении не изменяет уже установленный
системный VPN-профиль. Для применения новых настроек нужно подготовить новый
профиль в приложении и вручную установить его. Если локальный ID не указан,
приложение использует логин; сформированный профиль всегда содержит этот ID.
Если адрес VPN-шлюза и выходной адрес отличаются, USB-настройка может отдельно
передать `expectedExitAddress`. Поля в интерфейсе для него нет; адрес шлюза в
системном профиле от этого не меняется.

Установка самого IPA только с телефона этой схемой не выполняется: нужен
Windows-компьютер для подписи. После установки приложение работает на телефоне.

## Обновление подписи

Бесплатный профиль подписи действует 7 дней. Снова импортировать тот же IPA
в iLoader тем же Apple Account, чтобы получить свежий профиль, затем повторить
локальную переподпись указанной выше командой. Bundle ID и ключевая группа
приложения сохраняются, данные не очищаются. Apple может запросить повторный
вход или подтверждение. Путь Sideloadly остаётся альтернативой после исправления
его ошибки входа; автоматическое обновление этим способом сейчас не проверено.

Профиль VPN не привязан к 7-дневной подписи приложения, но соединение зависит
от сервера, срока сертификата и действительности учётных данных. Тестовый сервер
ограничен по времени и не является бессрочной услугой.

## Проверка профиля и подписи

Профиль — XML property list: PayloadType Configuration, внутри ровно один
com.apple.vpn.managed, VPNType IKEv2, AuthenticationMethod None,
ExtendedAuthEnabled 1, IncludeAllNetworks 0,
RemoteAddress/RemoteIdentifier/LocalIdentifier/AuthName/AuthPassword.
Проверка синтаксиса: `plutil -lint file.mobileconfig` на macOS или Python plistlib
на Windows; дополнительно сверить ключи со схемой Apple IKEv2. Это не заменяет
установку и проверку подключения на iPhone. Профиль не подписан и содержит пароль:
не публиковать его и не отправлять посторонним.

После переподписи проверить фактическую подпись отдельно: стандартные
application-identifier, com.apple.developer.team-identifier, keychain-access-groups
и get-task-allow возможны; никаких специальных VPN capabilities быть не должно.
Пустой отчёт unsigned IPA не доказывает права будущей подписи.
На установленной версии проверены ровно эти четыре ключа; App Groups отсутствует.
В подписанном Apple provisioning-профиле остаётся неиспользуемое разрешение
App Groups, но исполняемый файл его не запрашивает. Keychain-группа ограничена
этим приложением. Новый HTTPS-тест маршрута запускается при открытии приложения;
успех требует согласованного ответа двух независимых сервисов и совпадения с
ожидаемым выходным адресом. Это не заменяет проверку туннеля на сервере. Результат
без адресов и учётных данных сохраняется в Documents как `maykop-traffic-check.json`.

Для безопасной настройки по USB можно передать в Documents только этого
приложения файл maykop-test-config.json с configuration и password. Приложение
при открытии сохраняет пароль в Keychain и удаляет файл. Не хранить этот файл
в репозитории или общем облаке.
